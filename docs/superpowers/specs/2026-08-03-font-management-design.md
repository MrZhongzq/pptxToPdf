# admin 面板字体管理

2026-08-03

## 背景

字体是转换保真度的大头。pptx 只存字体名不存字形，字体缺失时渲染端会替换，
而替换字体的字符宽度不同，换行位置就变了。

现在提供自定义字体的唯一方式是：把文件拷进项目下的 `fonts-extra/`，然后重启
容器。这对自部署的人有三个问题——要有宿主机的 shell、要知道目录在哪、要会
重启容器。用群晖那类图形界面部署的人基本做不到。

## 目标

admin 面板里能查看、上传、删除字体，并且在上传会与已有字体打架时显式提示、
由管理员决定怎么处理。

### 非目标

- **不做字体预览渲染。** 要么起一个渲染服务，要么让前端加载几十 MB 的字体
  文件，两条路的成本都远超收益。
- **不做版权校验。** 放什么字体是部署者自己的判断。
- **不改 `fonts-extra` 的现有语义。** 它继续是只读的手工挂载点。

## 关键约束：一个文件可能包含多个字体

`.ttc`（TrueType Collection）是字体集合，一个文件里有多个 face，每个 face 有
自己的 family。这不是边缘情况——**微软雅黑就是 ttc**，Noto CJK 也是：

```
NotoSansCJK-Bold.ttc → Noto Sans CJK JP / KR / SC / TC / HK / Mono JP / ... （8+ 个）
```

因此：

- **冲突判定的粒度是文件，不是 face。** 替换和删除只能整个文件来，没法只动
  ttc 里的一个 face。
- 判定规则：上传文件的**任一** face 的 family，与已有文件的**任一** face 的
  family 相同，则该已有文件是冲突候选。
- 列表与弹窗都要显示"这个文件包含哪些字体"，否则管理员看不懂为什么会撞。

## 存储

字体文件存 `/app/storage/fonts/`。api 与 worker 都已挂 `storage` 卷，天然共享
且可写，不需要新的挂载。

fontconfig 通过 `deploy/fontconfig-local.conf` 里新增一条 `<dir>` 认这个目录。

**不建数据库表。** 文件系统就是真相来源，列表靠 `fc-query` 现扫。这样删掉文件
后列表自动一致，不会出现"DB 有记录、文件已不在"的孤儿态。上传时间取文件
mtime，原始文件名就是落盘的文件名。

落盘文件名做安全处理：只保留 basename，剥掉路径分隔符与 `..`，非法字符替换为
`_`。重名时在扩展名前加 `-2` / `-3` 递增后缀。

### 生效方式

写入后**立即生效**，不需要重启容器、不需要 `fc-cache`、不需要跨容器通知。

这是实测确认的：fontconfig 发现字体目录的 mtime 比缓存新时会自动重扫。在
worker 容器里直接写入一个字体文件后，未跑任何命令，`fc-list` 立刻能查到它。

## 字体元信息的提取

用 `fc-query`，fontconfig 自带，镜像里已经有，不引入 `fontTools` 依赖。

```
fc-query --format "%{family}\t%{style}\t%{fontversion}\t%{index}\n" <file>
```

每个 face 输出一行。字段说明：

- `family` / `style`：**各家命名不统一**（DejaVu 的常规体 style 是 `Book` 不是
  `Regular`），所以 style 只用于展示，冲突匹配一律只看 family。
- `fontversion`：定点数，显示时除以 65536。`155320 → 2.37`。
- `index`：face 在文件中的序号。

覆盖字数用 `%{charset}`，输出是十六进制范围列表：

```
20-7e a0-2e9 2ec-2ee 2f3 300-34f ...
```

按空格切分，每项是 `start-end` 或单个码位。

ttc 一个文件多个 face，用带 `\n` 的 format 调用时 fc-query 会按 face 换行分段
输出，每段各自求和后，**取覆盖最多的一段代表整个文件，不对多段求和**：ttc 里
的各 face 通常是同一字体针对不同语言区域的变体，字符集高度重叠（真机实测一个
10 face 的 Noto CJK，每段都是 44810 字），求和会把覆盖量算成 10 倍，而这个数字
的唯一用途是让管理员比较两个字体谁更全，虚高 10 倍就是误导。取最大值代表「这
个文件最全的那个 face 覆盖多少」。

## 冲突检测

上传的文件先落到临时位置，取出全部 face 的元信息并算 sha256，然后分三档：

| 判定 | 处理 |
| --- | --- |
| sha256 与某个已有文件相同 | 直接拦，告知已存在的文件名。没有歧义，不打扰管理员 |
| 存在 family 相同的已有文件（一个或多个） | 返回冲突候选，由管理员逐个决策 |
| 都不撞 | 直接接收 |

第二档匹配 **family 相同**而不是 family+style 都相同：范围放宽才能让管理员看见
全貌，漏掉一个的代价是事后两份字体打架，而 fontconfig 选谁是不确定的。

### 为什么不自动判断"是更新还是新字体"

**程序无法可靠回答这个问题**，所以不猜：

- 字体子集化很常见（网页版、精简版），family 和版本号可能都一样，只是字形
  少了一半。
- 厂商版本号不规范：有人改内容不改版本，有人重编译就跳版本。
- 同名不同厂的字体真实存在。

任何自动判断都会在某些字体上出错，而出错的表现是管理员莫名其妙丢了字体。
所以程序只做能确定的判断（sha256 相同、family 相同），把不确定的转成事实
对比交给人。

**「覆盖 N 字」是对比里最有用的一列**——版本号看不出子集化，字数能。真升级
通常字数持平或增加，掉一大截基本是精简版，换上去中文会缺字。

## 交互

### 冲突弹窗

```
上传的字体与下列已有字体可能是同一个，请逐个确认：

┌────────────────────────────────────────────────┐
│ 你上传的： msyh.ttc                             │
│ 包含：微软雅黑、Microsoft YaHei UI              │
│ 版本 6.30 ・ 覆盖 28,762 字 ・ 19.2 MB          │
└────────────────────────────────────────────────┘

☐ msyh-old.ttc          ← 完全同名
     微软雅黑、Microsoft YaHei UI
     版本 6.25 ・ 覆盖 28,762 字 ・ 19.1 MB ・ 07-15 上传
     ⚠ 你上传的版本更新

☐ msyhl.ttc
     微软雅黑 Light
     版本 6.30 ・ 覆盖 21,304 字 ・ 12.1 MB ・ 07-15 上传
     字数比你上传的少 7,458 个

☐ msyhbd.ttc   （手工挂载，不可替换）
     微软雅黑 Bold

        [ 替换勾选的字体 ]
        [ 这是一个新字体，直接添加 ]
        [ 取消上传 ]
```

用**勾选框**而不是每行一个「更新它」按钮：一次可能要替换多个（旧字体拆成三个
文件、新的合并成一个），勾选能表达而单按钮不能。每行独立控制，全局动作放底部。

`fonts-extra` 手工挂载的与镜像内置的**参与冲突提示但不可勾选**——它们不在面板
管辖范围内，删不掉，列出来只是让管理员知道名字被占了、自己传的可能不生效。

### 面板列表

侧边栏新增「字体」。按来源分三组：

- **面板管理**（`/app/storage/fonts`）：可删
- **手工挂载**（`/usr/share/fonts/truetype/extra`）：只读。api 容器已经以
  `:ro` 挂了这个目录（本次收尾前刚补上的），能读到，删不掉——正好是想要的
- **镜像内置**：只读，默认折叠（300+ 个）

每项显示：文件名、包含的字体名、版本、覆盖字数、大小、上传时间。

支持一次选多个文件上传，冲突逐个处理。

## 接口

```
GET    /api/admin/fonts              列表，按来源分组
POST   /api/admin/fonts/preflight    上传前检查，返回冲突候选
POST   /api/admin/fonts              落盘，带 replace 列表
DELETE /api/admin/fonts/{id}         删除
```

拆成 preflight + 提交两步，是为了让弹窗在**文件已上传完但未落盘**时决策。否则
要么先落盘再回滚，要么让管理员重传一遍。

preflight 把文件存到 `/app/storage/fonts-tmp/<token>`（token 是随机 uuid）并
返回该 token，提交时凭 token 落盘。

临时文件 TTL **30 分钟**——足够管理员看完对比表做决定，又不会让放弃的上传
长期占盘。回收**不复用 uploads 的回收器**：那个回收器绑在 uploads 表上，而
这里没有表。改为在 preflight 入口顺手清理本目录下 mtime 超过 TTL 的条目，
省掉一个后台任务。

`id` 用文件名的 URL-safe 编码，不用自增主键——没有 DB 表。

全部接口要求 admin 身份，复用现有的 `require_admin` 依赖。

## 边界与错误处理

- **上传的不是字体**：`fc-query` 无输出或退出码非 0 → 400，"这不是可识别的
  字体文件"。
- **只接受 `.ttf` / `.ttc` / `.otf`**：扩展名与 `fc-query` 双重校验，扩展名对但
  内容不是字体的一样拦。
- **单文件大小上限 64 MB**：不沿用 pptx 那个 600MB 的限制——它对字体毫无
  意义。实际参照：`msyh.ttc` 约 19 MB，Noto CJK 全集约 20 MB，64 MB 有充足
  余量。超限返回 413。
- **删除的文件不存在**：404，而不是静默成功——静默会让管理员以为删掉了。
- **replace 列表里有不可替换的项**（手工挂载/内置）：400，明确拒绝，不静默跳过。
- **磁盘写满**：写入失败要清掉半个文件，不能留下损坏的字体让 fontconfig 去扫。

## 测试

后端：

- `fc-query` 输出的解析：多 face 的 ttc、单 face 的 ttf、fontversion 定点数换算、
  charset 范围求和。用固定的样本输出做单测，不依赖真实字体文件。
- 冲突判定：sha256 命中、family 命中（含 ttc 的任一 face 命中）、都不命中。
- 文件名安全处理：路径穿越、非法字符、重名递增。
- 接口鉴权：非 admin 一律 403。

前端：

- 冲突弹窗的渲染与勾选状态。
- 三个全局动作各自发出的请求形状。
- 列表按来源分组、只读项不显示删除按钮。

不做端到端的真实字体上传测试——需要真字体文件，体积大且有版权问题。改为在
真机上手工验证一次。

## 落地顺序

1. 后端：`fc-query` 解析与冲突判定（纯函数，可单测）
2. 后端：四个接口
3. fontconfig 加 `<dir>`
4. 前端：列表面板
5. 前端：上传与冲突弹窗
6. 真机验证：传一个真的 msyh.ttc，确认转换时中文换行位置变化
